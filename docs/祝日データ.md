# 祝日データの登録・更新

出典は[内閣府「国民の祝日について」](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)と同ページの[CSV](https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv)。2026年18件・2027年17件を2026年10月10日に年別一覧と照合済み。振替休日と国民の休日を含む。祝日を計算で推定しない。

## Firestoreへの反映

同梱データはAPI起動時に自動同期しない。[ルートREADME](../README.md)の初期投入手順に従い、`seed-reference-data`を実行する。project/databaseを明示し、dry-runの確認後に`--apply`で反映する。本番では同手順の実行先を本番プロジェクトに合わせる。

祝日と公園を全件検証後、同じトランザクションで反映する。同梱年は`holidayYears`へ登録し、同梱データから外した年を削除する。空き状況データは保持する。初期投入後の更新は取得をpauseし、worker終了を確認してから実施し、反映後にresumeする。

チェックサムは編集・欠落の検出用で、公的に完全なデータであることの証明ではない。完全性は更新時の年別一覧との全件照合で確認する。未登録年を含む祝日検索は503を返す。

## 年次更新

運用担当者が毎年2月以降に翌年の公表を確認する。内閣府によると2028年分は2027年2月掲載予定。法改正等の臨時変更時にも確認する。公式からの自動取得は行わず、レビュー済みの同梱データを明示的に登録する。

1. 内閣府のCSVをダウンロードする。
2. `apps/api`で下記を実行し、必要な年をすべて指定する。同梱ファイル全体を生成し直すため、維持したい年も指定する。未公開年・不正形式の場合はファイルを変更しない。
3. 生成差分の全日付・名称・件数を公式の年別一覧と照合する。CSVだけでは年末の欠落等を判定できない。`verifiedAt`も照合日と合わせ、確認前に登録しない。
4. APIの`npm test`とDockerエミュレータ接続付き`npm run test:firestore`を実行し、追加年の検索確認を加えてPRでレビューする。
5. レビュー済みコードを配置し、`seed-reference-data`で反映する。Firestoreの件数・出典・登録年度と祝日検索を確認する。

```sh
curl --fail --show-error --location --max-time 30 \
  https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv -o /tmp/akicourt-holidays.csv
# apps/apiで実行。翌年公開後は維持年と追加年を列挙する。
node scripts/prepare-holidays.cjs /tmp/akicourt-holidays.csv 2026 2027
```

CSVはShift_JIS。生成スクリプトは既知のCSV形式以外を拒否するため、公式の形式が変わった場合は生成処理を見直す。新規年を追加した場合はテストの対象年・件数も公式確認後に更新する。DBの完了記録だけを手動追加しない。
